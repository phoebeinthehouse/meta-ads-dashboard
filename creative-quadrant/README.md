# MANYO Creative Quadrant (추가 페이지 · 베타)

기존 미국 Meta Ads Dashboard를 변경하지 않고, 별도 `creative-quadrant/index.html`에서 **실측 ROAS(X) × Meta 링크 CTR(Y)** 4분면을 제공합니다.

## 사용 흐름

- 기존 GitHub 대시보드와 같은 Apps Script 데이터를 `meta-raw-new`, `amz-raw-new`, `meta-ads-list`에서 읽습니다. 페이지 로드 시 요청하고 `↻ 최신 데이터 불러오기`로 재요청합니다.
- 2026-08-01 이후 소재를 월 단위로 자동 추가합니다. 기본 화면: 상시 소재, 파트너십 제외. BD(8/28–9/7), PBDD(10/6–7), HBE(10/19–31) 기간은 프로모션으로 분리합니다.
- 월·제품·소재명·최소 광고비·Attribution 매칭 여부 필터, 실측 ROAS·CTR 기준선 조정(표시 소재 중앙값 가능), 사분면별 대표 이미지, 전체 소재 목록, 광고 원본 링크를 제공합니다.
- 광고비에 비례한 버블 크기, 영상은 대표 썸네일로 표시합니다. 이미지가 깨지면 실제 Google Drive 원본 링크를 이용하세요.
- 실제 ROAS = 연결된 Amazon Attribution 원화 매출 / Meta 광고비 × 100. **내부 추정 ROAS(×2.5)와 다르며, 100%는 손익분기점이 아닙니다.**
- Attribution이 매칭되지 않은 소재는 ROAS **미확인**으로 남기고 0%로 간주하지 않습니다.

## 보안 — 공개 배포 전 확인 필수

**GitHub 저장소 `phoebeinthehouse/meta-ads-dashboard`는 PUBLIC입니다. GitHub Pages로 이 페이지를 배포하면 링크를 아는 외부인도 앱을 열 수 있으며, 현재 Apps Script 데이터 소스가 공개 접근 가능하다면 광고비·매출과 소재 실적도 볼 수 있습니다. HTML에 `noindex`를 넣어도 접근 제어가 되지 않습니다.**

PR에는 실측 데이터 CSV, 광고 이미지 파일, 광고비·매출 숫자가 **커밋되지 않습니다.** 하지만 실제 브라우저 데이터 호출 자체를 제한하려면 회사 SSO 또는 Cloudflare Access 같은 인증된 호스팅/프록시가 필요합니다. **권한 정책 확인 전에는 GitHub Pages 배포하거나 본 PR을 merge하지 마세요.**

## QA · 제한 사항

- 원본 API의 실제 CORS/공개 범위/이미지 M열 링크는 라이브 환경에서 별도 QA가 필요합니다.
- 예제 CSV 파일을 사용한 정적 브라우저 테스트에서 페이지 로드, 소재 조인, 분면 필터, 0건과 미확인 매출 분리, CSV 가져오기, 클릭 상호작용은 검증했습니다. **실제 Apps Script 연결 및 기존 대시보드의 복잡한 Attribution 배분 규칙과의 수치 일치는 아직 검증되지 않았습니다.**
- 본 페이지의 소재-구매 연결은 `월 × 제품 × 정규화된 소재명 × 행사구분 × 파트너십 여부` 기준입니다. 기존 `index.html`은 중복 및 캠페인별 배분을 더 정교하게 처리하므로 특히 중복 캠페인 사례는 꼭 검증하세요.
- 현재 사이트는 2026년 8월 이후 자료를 기본 대상으로 합니다. 이전 2025년 자료까지 포함하려면 기간 처리 변경이 필요합니다.
- 실시간 로드가 차단될 경우 사용자 본인의 브라우저에서 원본 탭 CSV 2개(이미지 매핑 선택)를 직접 업로드해 사용할 수 있습니다.
